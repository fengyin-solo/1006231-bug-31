# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。
- 业务逻辑测试：`cd frontend && npm run test`（vitest，覆盖权限、写回、迁移与去重）。

## 泄洪操作的受控口径（定稿）

泄洪操作涉及越权拦截、台账写回与历史数据迁移，决策如下，改动需同步本节：

- **责任班组**：泄洪记录带「责任班组」。`开启泄洪`/`结束泄洪` 只允许责任班组执行，
  越权提交直接挡回，提示里写清记录归属班组与当前班组；操作成功后「操作人员」记成实际
  操作人，不再出现替别人操作还记原班组的情况。当前班组/岗位在顶栏切换（会话存
  `stores/session.ts`）。
- **台账写回**：`结束泄洪` 时把「开启孔数 → 当前开度、泄洪流量 → 泄洪流量」一次性写回
  闸门台账（按泄洪闸号 = 闸门编号匹配），泄洪列表、闸门启闭页与另存的泄洪记录读同一份
  数据。泄洪记录带「台账写回」标记，同一操作重复提交只生效一次，不会重复写回孔数。
- **结论回写**：`结束泄洪` 的同时把结论写进「检修待办」（`todo` 模块），按
  「来源单号 = 操作编号」去重，重复登记只认第一次、先入库的保留。运营概览的
  「检修待办 · 待处理」与待办页的待办合计、概览页的提醒事项读同一份数据，条数天然对应。
- **只读入口**：泄洪记录的「另存（导出）/ 档案」是受控只读入口，仅「泄洪值守岗」可用，
  权限外的越权操作一律拦截并提示。
- **导入去重**：导入按业务编号（各模块第一个字段，泄洪即操作编号）去重，重复导入只保留
  一次，不会因此多出一行；泄洪记录的导入与另存同口径，仅本岗位可用。

### 历史数据迁移（v1 → v2）

老数据打开时自动迁移（`frontend/src/data/migrate.ts`，版本戳存在
`hydropower-plant-om:meta`），迁移幂等，重复执行不会多出行。顺序定稿：

1. 补齐模块桶：老数据没有后加的模块（如检修待办），先补空数组。
2. 闸门台账补「泄洪流量」字段，默认 `0`，给写回备好落点。
3. 泄洪记录补「责任班组」与「台账写回」标记。早期没有责任班组的按**操作时间**推断：
   白班 08:00-20:00 记「运行一班」，其余时段记「运行二班」；操作时间缺失或解析不出
   时刻的，按现行版别默认记「运行一班」。
4. 历史已结束且未写回的泄洪记录按**操作时间升序**写回闸门台账：同一闸门多次泄洪时
   时间最新的一次最终生效；写完标记「已写回」。
5. 已结束的泄洪记录逐条补登记检修待办：登记日期按泄洪操作时间（发生日期）回填，
   其余缺项按现行版别推断（结论按当前模板生成、责任班组沿用第 3 步结果）；
   按来源单号去重，先入库的保留。
