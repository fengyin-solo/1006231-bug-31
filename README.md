# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 泄洪操作的受控规则

泄洪（`flood`）与闸门台账（`gate`）、后续检修待办是同一份数据，集中在
`src/data/migrations.ts` 与 `src/api/local-service.ts` 里保证一致：

- **归属与越权**：开启/结束泄洪只允许记录的「责任班组」的泄洪操作工执行；非泄洪岗位、
  或泄洪岗位但非本班组的提交一律在服务层挡回，并写清该操作归属哪个班组。操作记录如实
  记录实际操作人，不再沿用原班组的操作人。页面按钮只做展示收敛，绕过页面直接调动作照样被拦。
- **台账一次性回写**：开启时台账同步运行孔数；结束泄洪时把「开启孔数、泄洪流量」一次性
  写回闸门台账（闸门全关但保留本次实际开启孔数）。泄洪列表页的「闸门台账孔数」列、闸门
  启闭页、导出的另存记录读的是同一份。记录上带 `台账已回写` 标记，同一操作重复提交只生效
  一次，不会重复写回孔数/流量。
- **后续检修待办同步**：结束泄洪自动生成一条待办，泄洪页的只读受控入口（仅泄洪操作工）
  与机组检修页的「泄洪后续检修待办」读同一份，条数对应、实时同步；按操作编号去重，
  先入库那份保留，重复不新增行。
- **登记/导入去重**：操作编号即业务主键，登记与批量导入遇到重复编号整份跳过，取值只认
  第一次入库的。
- 纯逻辑自检：`cd frontend && npm run verify:logic`（用 esbuild 打包后在 Node 里跑断言，
  覆盖迁移、越权、台账回写、幂等、待办同步、导入去重）。

### 数据迁移顺序与缺项补记

本地数据带 `version`（当前 v1）。老结构（扁平的 `{模块: 行[]}`）或低版本数据在读取时按
固定顺序迁移，且每步幂等、可重复执行。v0 → v1 的顺序：

1. 闸门台账补「开启孔数 / 泄洪流量」两列（缺省 `0孔`、`0m³/s`）；
2. 泄洪记录补缺项：**早期没有责任班组的，按闸号尾号奇偶归属——偶数归泄洪二班、奇数（含
   无法解析）归泄洪一班，并打「历史补记」标记**；缺开启孔数先取台账该闸号现行值、再缺按
   最小开启单位 `1孔`；缺泄洪流量按 `0m³/s`；缺操作时间按 `1970-01-01` 排到最早回填；
   缺操作人员记「历史值守（待核）」；已结束缺结束时间用操作时间补；
3. 历史泄洪记录按操作时间从早到晚依次核对回填台账，同一闸门多次泄洪以最晚一次为准，
   每条已结束记录只写回一次；
4. 为全部已结束记录按结束时间生成后续检修待办，操作编号去重、先入库保留。
